# Wylie College 课程注册系统

软件工程课程设计 · 五人协作学习参考实现 · v1.0.0

代码注释中的“成员A–E”均为建议责任分配，实际贡献需据实记录。

## 1. 启动（Python 3.10+，验证环境 Python 3.12.3）

在本目录打开终端：

```bash
python -m venv .venv
# Windows PowerShell：.venv\Scripts\Activate.ps1
# Linux / macOS：source .venv/bin/activate
python -m pip install -e ".[test]"
python -m flask --app crs init-demo
python run.py
```

打开 http://127.0.0.1:5000 。停止服务：Ctrl+C。

首次安装需要下载依赖；启动后的页面无 CDN、外部字体或在线服务依赖。业务、模拟目录、模拟计费分别保存在 `instance/` 的三个 SQLite 文件。`run.py` 使用 Waitress、8 个线程，只监听本机；不启用调试器。

|角色|账号|密码|建议用途|
|---|---|---|---|
|注册员|admin|admin123|维护人员、结束加退选、关闭注册、重发账单|
|学生|s1|123456|查看历史成绩、创建完整课表|
|新生|s18、s19|123456|先修课失败、并发抢最后名额|
|计算机系教授|p1、p2、p3|123456|选择授课、查看花名册、录入成绩|
|数学系教授|p4、p5|123456|数学课程成绩与授课|

学生共 s1–s20；教授 p1–p6，p6 为退休状态。全部人物和号码均为演示合成数据。

## 2. 可复现验证

```bash
python -m pytest -q --cov=crs --cov-report=term-missing
python scripts/benchmark.py --output results/benchmark.json
```

测试使用临时目录，不污染演示数据库。性能脚本是 20 线程、200 次进程内查询的本地抽样，不能代表 2000/500 并发用户验收。

重置演示前停止服务，按需备份 `instance/`：

```bash
python -m flask --app crs init-demo
```

已有数据时会询问确认。自动化环境可显式使用 `init-demo --yes`。禁止在服务运行期间重建数据库。演示加退选截止自动设为初始化时刻之后 21 天；历史学期固定为 2026 春。

## 3. 八个用例

1. 登录：密码哈希、会话、角色边界。
2. 维护学生：增改查删，历史数据删除保护。
3. 维护教授：增改查删，账号同步。
4. 注册课程：草稿、提交、更新、删除，先修课、时间、容量校验。
5. 选择授课：院系资格、独占认领、时间冲突校验。
6. 提交成绩：只允许任课教授操作上一已关闭学期；A/B/C/D/F/I，空值跳过。
7. 查看成绩单：会话身份限定本人，密码再次确认，响应禁止缓存。
8. 关闭注册：截止守卫、无教师取消、备选补位、3–10 人检查、事务性计费发件箱。

## 5. 明确边界与待确认口径

- 技术采用 Flask + 服务端模板 + SQLite 的分层单体。课程要求允许 Web 实现，因此以现代浏览器替代题目年代的 Windows 95/98 桌面界面。
- Ingres/VAX 和 Billing 均用独立 SQLite 模拟；没有声称真实接入校方系统。
- 原文“4 首选＋2 备选”：界面支持完整 4＋2；本实现暂按“最多4＋最多2、提交至少1门首选”处理加退选场景。**需教师确认**首次提交是否必须恰好4＋2，确认后在 `_validate_selection` 集中修改并补测试。
- 备选不占名额；关闭时依次尝试。当前公平性采用课表最后更新时间、课表ID稳定排序；它是示例口径，不保证最大全局录取率。
- 关闭按原文单轮处理：补位后仍不足3人则取消，不再次反复补位。最终可能少于4门。
- `CLOSED` 同时用作“可录入成绩的已关闭学期”；原题“学期结束”没有独立教学日历。教师应确认是否增设教学结束日期守卫。当前演示关闭后即可录入该学期成绩。
- 学费按 600 元/学分的演示假设计算；只给有最终确认课程的学生生成账单。
- 安全措施限定基本角色检查、归属校验、密码哈希、CSRF 和成绩二次确认；默认演示密码不可用于真实部署。
- SQLite 写事务串行；已验证最后一个名额不会被两人同时抢占。大规模容量、长时间可用性、Windows 实机、真实网络故障与灾难恢复演练尚未验证。
- 缓存是进程内 TTL 缓存；同进程同学期冷启动只拉取一次。已有缓存可在TTL内继续服务，过期后源系统故障会明确报错。
- 服务层是可信内部边界；角色鉴权在 Web 层，对象归属在服务层和会话取值处落实。不要把内部方法直接暴露为未鉴权接口。
