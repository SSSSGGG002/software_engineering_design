# 概要与详细设计

版本1.0｜与参考实现对应｜ClawsGO Science Agent

## 1. 架构选择

浏览器 → Flask蓝图（身份、表单、呈现）→ 服务层（业务规则与事务）→ SQLite本地库 / 外部系统适配器。分层单体在五人规模下便于理解和集成。没有ORM、微服务、Redis或消息队列；复杂度集中在业务一致性。

目录基础课程只读；授课教授、开课状态等新系统状态放在本地offering_state，避免写入遗留数据库。缓存只缓存目录，不缓存座位数，容量始终读本地已注册条目。

图见 diagrams/architecture.svg、use-cases.svg、domain-model.svg、registration-sequence.svg、semester-state.svg；同目录含可编辑DOT源与PNG版本。

## 2. 领域与数据字典

|表|主键 / 约束|含义与生命周期|
|---|---|---|
|student|id；ssn唯一|人员资料；历史引用存在则业务层拒绝删除|
|professor|id；ssn唯一|资料、院系、状态；退休禁止新增授课|
|user_account|id；username唯一|角色、人员外键、哈希；删除人员级联关闭账号|
|semester|code；seq唯一；OPEN部分唯一索引|PLANNED/OPEN/CLOSED；加退选截止与关闭时间|
|offering_state|offering_id；学期与教授外键|遗留开课ID对应的本地状态；course_id快照|
|schedule|id；student_id+semester唯一|DRAFT/SUBMITTED；version乐观锁；更新时间|
|schedule_item|id；schedule_id+offering_id唯一|PRIMARY/ALTERNATE；priority；SELECTED/ENROLLED/COMMITTED/CANCELLED|
|grade|student_id+offering_id复合主键|成绩枚举、课程号、学期、录入教授与时间|
|billing_outbox|id；idempotency_key唯一|JSON课表、整数元金额、PENDING/SENT、重试时间|
|system_setting|key|外部系统可用性演示开关|

外部目录表：course、prerequisite、course_offering。模拟计费独立invoice表以idempotency_key主键去重。各库有明确所有权，禁止跨模块任意写表。

## 3. 核心类与职责

Database提供transaction/reader/using，连接不跨线程共享。AuthService负责登录；PeopleService负责建档和人员删除守卫；CatalogService负责TTL快照；OfferingQueries合并只读目录与本地状态；RegistrationService拥有课表原子修改；TeachingService拥有授课和成绩；SemesterService拥有注册周期守卫；ClosingService编排最终处理；BillingService只负责发送与重试。create_app集中依赖注入，FakeClock使时间边界可测试。

## 4. 事务与不变量

I1 每名学生每学期至多一张课表；I2 一个开课至多一个任课教授；I3占座条目不超过10；I4首选+实际补入备选不超过4；I5最终开课至少3人且有教授；I6账单金额等于最终课表学分和乘费率；I7任何被拒批量操作不部分生效。

数据库唯一键/外键负责I1及引用；单字段教授归属负责I2；BEGIN IMMEDIATE将名额检查与写入串行化以落实I3；服务层落实I4–I7。SQLite使用WAL和10秒busy_timeout。高并发吞吐属于明确限制，迁移到支持行锁的关系库需重新设计锁顺序与隔离策略，不能只换连接字符串。

## 5. 提交课表算法

1. 解析选课列表与学期；事务外取目录。
2. 校验重复、数量、本学期课程。
3. BEGIN IMMEDIATE；复核学期未切换、截止未到、学生在读。
4. 对课表版本做compare；创建或更新集合，暂时释放退选名额。
5. 先修课程从更早CLOSED学期的A–D成绩集中查询；校验首选开放、座位、时间。
6. 失败抛领域异常使整个事务回滚；成功标记ENROLLED、递增version、更新课表状态。
7. 在同一事务和目录快照内组装返回视图，避免提交后重新取目录失败造成错误的失败提示。

TimeSlot采用同一星期的半开区间比较；结束10:00与开始10:00允许相接。最多4门首选，两两比较足够清晰，无需区间树。

## 6. 关闭与计费

关闭是单个本地写事务，投递是事务提交后的独立过程。对端不可用时发件箱保留PENDING；重试间隔10、20、40秒，最高300秒。默认启动入口每5秒扫描，按next_attempt_at筛选。跨进程重复投递仍通过对端幂等键“学期:学生ID”消除重复账单。

崩溃窗口：
- 业务事务提交前崩溃：SQLite回滚，允许重新关闭。
- 业务提交后发送前崩溃：重启扫描PENDING。
- 对端接收后本地标SENT前崩溃：同一幂等键重发，接收端去重。

当前模拟接收端无真实网络超时；真实适配必须加连接/读取超时与按幂等键查询确认。后台线程异常写日志并继续，明确不把“调用一次发送”当成恰好一次交付。

## 7. 错误与边界

业务异常DomainError提供message/details；表单级错误保留输入。读页面发生目录故障直接呈现503页面，避免教授首页故障重定向到自身形成循环。表单更新使用POST+CSRF；身份从会话取，学生不能靠student_id参数查询他人。

内部服务在可信应用内调用。Web层的角色检查与服务层教授归属检查共同完成授权。只读读模型由多条查询构成，展示的人数可能瞬时变化；最终正确性由写事务保证。

## 8. 部署与配置

Python 3.10+，Flask、Waitress、SQLite。运行目录instance含三库与本地会话密钥；测试临时库独立。课程目录TTL为300秒，模拟延迟0.8秒，费率600元/学分。run.py是推荐启动入口；Flask CLI用于初始化/手工重试，不启动后台worker。

不得在服务运行时重置数据库。正式部署若需要联网使用，应先修改演示账号、启用HTTPS并进行容量和备份恢复验证；这些工作不在当前本机参考版的已验收范围。

## 9. 设计评审检查

由C解释名额不超卖，D解释成绩如何满足先修，E解释发件箱崩溃窗口，B解释人员删除为什么不能无条件级联，A解释缓存与本地开课状态分离。每人应能画出至少一个关联模块的事务顺序。
